# R190–R191 — the installer ships the repository

<!-- status: built -->

**Built.** Found while checking whether the `extract-zip` Dependabot alert reached the shipped
application. It does not — but answering the question meant opening `app.asar`, and what was
inside it was the finding.

**Result: 1202 MB -> 31 MB**, four top-level asar entries, and the packaged application launches
clean. Every acceptance criterion in § 7 met, including the mutation in 4 — which found a defect
in the guard's first version and is written up in § 9.

## 1. What is wrong

`electron-builder.yml`'s `files:` list contains **only negative patterns**. electron-builder's
default is `**/*`; a list of exclusions narrows that default rather than replacing it, so the rule
in force is *ship the entire working tree except these six patterns*.

Measured on the build of 2026-09-10 05:40, made with this configuration:

```
archive on disk : 1202 MB      dist/win-unpacked/resources/app.asar

by top-level directory:
   1166.3 MB  spike
     22.7 MB  node_modules
      2.7 MB  docs
      2.0 MB  test
      2.0 MB  out          <- the application
      0.3 MB  assets

largest entries:
    524.3 MB  /spike/fixtures/cars-500mb.xml
    209.7 MB  /spike/fixtures/cars-200mb.xml
    104.9 MB  /spike/fixtures/cars-100mb.json
    104.9 MB  /spike/fixtures/cars-100mb.min.json
    104.9 MB  /spike/fixtures/cars-100mb.xml
     52.4 MB  /spike/fixtures/cars-50mb.xml
```

plus `CLAUDE.md`, `.claude/`, `tools/`, `scripts/`, `probe-sandbox.mjs`, `vitest.config.ts` and
four `tsconfig*.tsbuildinfo` files at the root.

**The application is `out/` — eight files, 2.0 MB.** Everything else in that list is either the
repository's own working material or a test fixture.

## 2. Two consequences, and they are not the same size

**The 1.16 GB is local only.** `spike/fixtures/` is gitignored and generated by
`npm run fixtures:generate`; neither `ci.yml` nor `release.yml` runs it (grep: zero occurrences in
both). A tagged release therefore does **not** carry the fixtures. Anyone who has run the fixture
generator and then builds gets a 1.2 GB installer, which is how this was found.

**The rest ships everywhere, releases included.** These are tracked files, present on a CI runner
immediately after checkout:

| | files |
|---|---|
| `docs/` | 105 — every plan document, `DECISIONS.md`, `FINDINGS.md`, `LOG.md`, `TASKS.md` |
| `test/` | 171 — the whole suite and its fixtures |
| `assets/` | 29 — sources, already emitted into `out/main/chunks/` by `?asset` |
| `scripts/` | 3 |
| `.vscode/` | 3 |
| `tools/`, `.claude/` | 1 each |
| root | `CLAUDE.md`, `probe-sandbox.mjs`, `vitest.config.ts`, `electron-builder.yml`, `package-lock.json`, `.editorconfig`, `.gitattributes`, `.stylelintrc.json`, `tsconfig.lib.json`, `tsconfig.worker.json` |

This is not a security hole — nothing here is a secret, the repository is public, and none of it
executes. It is a correctness and size problem: a viewer that carries its own test suite and its
internal design notes is shipping something nobody asked for, and a downloader has no way to tell
the application from the workshop around it.

## 3. Why a blocklist was always going to end up here, with the proof in the file

The exclusion list is not merely incomplete; it is **stale in a way that is visible on its face**.
It names three tsconfigs:

```yaml
- '!{tsconfig.json,tsconfig.node.json,tsconfig.web.json}'
```

The repository has five. `tsconfig.lib.json` and `tsconfig.worker.json` were added afterwards and
nobody went back to the packaging config, because nothing makes you. It excludes `README.md` and
not `CLAUDE.md`, for the same reason: `CLAUDE.md` did not exist when the line was written.

**Every file added to this repository ships by default and stays shipping until someone remembers
this file.** That is the defect. The 1.2 GB is a symptom dramatic enough to notice; the two
tsconfigs are the same defect at a size nobody would ever have noticed, and they had been shipping
for months.

This is R47's finding in a new place — four real lint errors under 5,363 CRLF warnings is how a
tool gets switched off — and `CLAUDE.md`'s own § "Spikes" argues the same way about the M0a
harness's lockfile. A default that must be actively narrowed rots; a default that must be actively
widened cannot.

## 4. R190 — replace the list with an allowlist

```yaml
files:
  - out/**
  - package.json
  - LICENSE
```

`out/**` is the built application: `out/main/index.js`, `out/preload/index.js`, `out/renderer/`
and the `?asset` outputs electron-vite emits into `out/main/chunks/`. `package.json` is required —
Electron reads `main` from it. `LICENSE` is deliberate: the MIT text is a condition of
distributing the thing, and it costs a kilobyte.

**`node_modules` is deliberately absent, and this had to be verified rather than assumed** —
`docs/PLANNING.md` § 2. electron-builder does not walk production dependencies through the `files`
matcher; its app file walker skips `node_modules` and a separate collector driven by the
production dependency tree handles it. Verified by building with exactly the three patterns above
and censusing the result:

```
archive on disk : 31 MB
by top-level directory:
   22.7 MB  node_modules      <- present, though `files` never mentions it
    2.0 MB  out
    0.0 MB  LICENSE
    0.0 MB  package.json
```

Four top-level entries. **1202 MB -> 31 MB.** The packaged application launched from
`dist/win-unpacked/Klados.exe`: main, renderer, GPU and utility processes all up, nothing on
stderr.

**Not a `spike` exclusion added to the existing list.** That fixes the 1.16 GB and leaves § 3
exactly as it is, which is the whole point — the next directory added to the repository would
ship, and the round would have been spent on the symptom.

**Not `asar: false`, not `extraResources`, not `directories.app`.** None of them is what is wrong;
the `files` default is.

## 5. R191 — a guard, because § 3 says discipline will not hold

`CLAUDE.md` invariant 10's phrasing is the standard: *enforced by test, not discipline.* Nothing
in R190 prevents someone adding a `**/*` or a negative pattern back, and § 3 is an argument that
they eventually will.

`test/packagedFiles.test.ts` reads `electron-builder.yml`, resolves its `files` patterns against
the repository's own top-level entries, and asserts the resulting set. It fails if a pattern is
negative, if anything outside `package.json` and `LICENSE` is selected, or if the application's own
entry points go missing.

**Reading the directory rather than `git ls-files`.** The first sketch shelled out to git, which
would have been the first test in the suite to do so — a dependency on git being on `PATH` and on
the working tree being a checkout, for no gain here. `readdirSync('.')` answers the same question,
and reading the *real* directory rather than a hardcoded list is what makes the test cover a
directory added after it was written. `out/`, `node_modules/`, `dist/` and `.git/` are skipped by
name, for the reasons the test states at that line.

**What it proves and what it does not.** It proves the *configuration* selects the right set of
repository files. It does not run electron-builder and so does not prove the *pack* — that was
verified once by measurement in § 4, and is re-verified by anyone who builds. Saying so here
rather than letting the test's name imply more than it does; R115 is the round that cost.

**Not a CI packaging job.** `ci.yml` excludes packaging on purpose (R141) and a full pack per pull
request would trade several minutes a run for a check the config-level test already makes. The
release workflow builds for real, and § 4's census is the procedure to repeat if it is ever in
doubt.

## 6. Cost

The test resolves three patterns against the ~30 top-level repository entries with no glob
dependency — the pattern vocabulary here is a literal and a `/**` suffix and nothing else, so it is
a prefix test and an equality. **Measured: 6 ms**, node project. **No new dependency**
(`CLAUDE.md` § Conventions).

## 7. Acceptance

1. `files:` contains no negative pattern.
2. A `--dir` build's asar has exactly four top-level entries: `out`, `node_modules`,
   `package.json`, `LICENSE`; and is under 50 MB with `spike/fixtures/` present on disk.
3. The packaged application launches.
4. `test/packagedFiles.test.ts` fails when a `**/*` pattern is added to `files:` and when a
   negative pattern is added — verified by mutation, not by a green suite (R183's standard).
5. `npm test`, `npm run typecheck`, `npm run lint` clean.

## 8. Version

**No bump.** Standing decision: 1.0.0 until first release. This changes what the first release
contains, which is an argument for landing it before that release rather than for renumbering
anything.

### What the review found

**The guard's first version reported a pass it had not earned.** `selects()` returned `false` for
any pattern outside its vocabulary. Adding a broad glob to `files:` therefore turned the vocabulary
assertion red — but left *"ships nothing else the repository contains"* **green**, because the
matcher did not recognize the pattern and so concluded nothing was selected. The most important
assertion in the file was passing on a configuration it had not understood.

This is only visible by running the mutation and *reading which assertions failed*, rather than
observing that the suite went red. §7's criterion 4 asks for the mutation for exactly this reason,
and R183 established the standard. `selects()` now throws on an unrecognized pattern, and a third
mutation — `docs/**`, well-formed and inside the vocabulary — confirms the assertion catches what
only it can catch:

| mutation | vocabulary | selects exactly | ships nothing else | ships the app |
|---|---|---|---|---|
| `!src/*` | ✗ | ✗ | ✗ | ✗ |
| `**/*` | ✗ | ✗ | ✗ | ✗ |
| `docs/**` | ✓ | ✗ | **✗** | ✓ |

Also corrected in review: § 5 and § 6 described a `git ls-files` implementation that was not what
landed, and a path count that went with it.

### Owed

**Nothing.** All five acceptance criteria met.

### Not done, deliberately

**The `node_modules` payload is untouched at 22.7 MB**, and roughly half of it is React's
development and server builds (`react-dom-profiling.development.js` and friends, 1.1 MB each)
that an Electron renderer never loads. That is a separate question from this round's — which was
about the *repository* being in the package — and answering it means deciding whether to prune a
dependency tree by hand, which is a different kind of risk. Recorded here rather than in the Owed
table because it is not something this round undertook to do.
